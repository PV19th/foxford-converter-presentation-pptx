# Конвертер презентаций Фоксфорда

Внутренний сайт для методистов: загружаешь старую презентацию урока (.pptx), выбираешь шаблон и варианты слайдов — получаешь файл в новом шаблоне, превью всех слайдов, сверку текста и памятку, что проверить вручную. По кнопке «Доработать с ИИ» ИИ поправляет раскладку слайдов, которые пометил конвертер.

Подробная инструкция для Claude Code и все решения автора — в `CLAUDE.md`. Этот файл — короткая справка для человека.

## Шаблоны на сайте

- **Фирменный шаблон 5–11 · 4:3** и **Фирменный шаблон 5–11 · 16:9** — для старых уроков 5–11 классов и уроков ЕГЭ. Класс, номер урока и предмет вводятся на сайте; титул, прощание и служебные слайды выбираются по миниатюрам.
- **Индивидуальные шаблоны** (выпадающий список) — личные шаблоны преподавателей. Сейчас один: **Авраменко В.** Класс и урок не спрашиваются: теги переносятся со старого титула.
- «Сегмент 5–11 (как в 5.8 и 6.4)» скрыт с сайта и остаётся для регрессионных тестов.

Статус: сайт работает локально в Docker; ИИ-доработка подключена через посредника DS Lab. Сервер и инструкция для IT (`DEPLOY.md`) — следующий этап, требования к серверу — `docs/Требования_к_серверу.md`.

## Как запустить сайт у себя

Нужен Docker Desktop.

1. Скопируйте `.env.example` в `.env` и впишите пароль (`APP_PASSWORD`) и случайную строку (`SECRET_KEY`). Для кнопки «Доработать с ИИ» — ключ DS Lab (`ANTHROPIC_BASE_URL`, `ANTHROPIC_AUTH_TOKEN`); без ключа сайт работает, кнопки нет.
2. Запустите:

```bash
docker compose up -d --build
```

3. Откройте http://localhost:8000. Остановить: `docker compose down`. Журнал: `docker compose logs -f` или `data/logs/app.log`.

После изменения кода, шаблонов или правил ИИ — снова `docker compose up -d --build`.

## Что где лежит

- `converter/` — отлаженный конвертер «по правилам» для фирменных шаблонов. Логику менять только по решению автора (см. `CLAUDE.md`); новые правила записываются в `docs/Чек-лист_переноса.md`. `fix_*.py` — примеры ручной доводки, сайтом не используются.
- `app/reskin.py` — перенос «пересадкой» для индивидуальных шаблонов: слайды садятся на макеты нового шаблона, цвета перекрашиваются по таблице профиля.
- `app/pipeline.py` — обработка одной презентации: конвертация → сжатие → сверка текста → превью → памятка.
- `app/ai/` — ИИ-доработка. Правила для ИИ — `app/ai/prompt.md` (обычный текст, его можно править без программиста).
- `app/main.py` — сайт (вход по паролю, загрузка, результат); `app/jobs.py` — очередь; `app/web/` — страница.
- `app/texts.py` — тексты памятки и сообщений: их можно править без программиста.
- `templates/<шаблон>/profile.json` — настройки шаблона: название и группа на сайте, база, варианты слайдов (`choices`), для индивидуальных — таблица цветов. Миниатюры вариантов — `templates/<шаблон>/thumbs/`.
- `base/` — шаблоны (`template_4x3_v01_26.pptx`, `template_16x9_v01_26.pptx`, `template_avramenko_16x9_v01_26.pptx`) и старые базы `ex58`, `ex64`. `base/generated/` собирает `tools/build_base.py` (при сборке Docker-образа).
- `tools/` — сборка базы, миниатюры шаблона (`template_previews.py`), сжатие слишком большого шаблона.
- `tests/` — прогон тестовых презентаций и отпечатки эталонных результатов (`tests/baseline/`).
- `browser/` — пробная версия «в браузере»: сайт без серверной части, перенос идёт в браузере методиста, без превью и ИИ. Альтернатива, не замена; папку можно удалить целиком (см. `browser/README.md`).
- `docs/` — чек-лист правил переноса, карта шаблона и листы миниатюр, требования к серверу, README конвертера, отчёты по переносам.

## Как проверить (нужен Docker)

Одна презентация из командной строки:

```bash
docker compose run --rm -v "$PWD:/srv" app python3 -m app.pipeline "test_inputs/old/5.21 ….pptx" outputs/5.21 5.21 --template foxford_5-11_v01_26
```

Все тестовые презентации профиля — результат в `outputs/tests/<профиль>/index.html`, превью рядом с правкой методиста; отпечатки сверяются с `tests/baseline/`:

```bash
./tests/run_all.sh --template foxford_5-11_v01_26
./tests/run_all.sh --template foxford_5-11_16x9_v01_26
./tests/run_all.sh --template avramenko_16x9_v01_26
./tests/run_all.sh
```

(последняя строка — скрытый профиль «Сегмент 5–11»). ИИ-доработка готового прогона: `docker compose run --rm -v "$PWD:/srv" app python3 -m app.ai outputs/tests/<профиль>/<урок>` — стоит денег, расход пишется в `data/ai_usage.json`.

## Секреты и материалы уроков

Пароли и ключи хранятся только в `.env` (не попадает в репозиторий). Образец — `.env.example`.

Тестовые презентации (`test_inputs/`: старые уроки, принятые методистом переносы, примеры правок после ИИ) и результаты (`outputs/`, `data/`) в репозиторий не попадают — это материалы уроков. Как раскладывать файлы — в `test_inputs/*/ПОЛОЖИТЬ_СЮДА.txt`.

## Стикеры

Папки `assets/` со стикерами нет: на место стикера конвертер ставит старый стикер из исходника, а методист меняет его на актуальный — это пункт памятки «Проверьте вручную».
