# Конвертер презентаций Фоксфорда → веб-приложение

Этот файл — постоянная инструкция для Claude Code. Читай его в начале каждой сессии.

## Что строим

Внутренний сайт для методистов Фоксфорда. Автор отправляет коллегам ссылку, они входят по общему паролю. Коллега загружает старую презентацию урока (.pptx), выбирает шаблон, класс и номер урока и получает файл в новом шаблоне, превью всех слайдов и отчёт о том, что проверить вручную. Базовая конвертация работает без ИИ: сайт запускает готовый конвертер из `converter/`. ИИ подключается позже как дополнительный движок (см. «Развитие»).

Пользователи не программисты. Интерфейс на русском, максимально простой: одна страница, понятные ошибки.

Сайт = страница (HTML/CSS/JS без фреймворков) + серверная часть на Python (FastAPI) в Docker. Чисто статический сайт невозможен: конвертеру нужны Python, LibreOffice и шрифт на сервере.

## Развитие: закладывать сразу

- **Несколько шаблонов.** Всё, что относится к шаблону, — в профиле `templates/<имя>/profile.json` (название для сайта, порядок, классы, база, доноры, варианты слайдов на выбор — `choices`, заглушки). Пользователь выбирает шаблон на сайте (полоса выбора видна, только когда шаблонов больше одного). Сейчас три профиля: «Фирменный шаблон 5–11 · 4:3» (`foxford_5-11_v01_26`, см. «Этап 6»), «Фирменный шаблон 5–11 · 16:9» (`foxford_5-11_16x9_v01_26`, см. «Шаблон 16:9») и «Сегмент 5–11 (как в 5.8 и 6.4)» (`segment-5-11`: ex58 для 5 класса, ex64 для 6-го; скрыт с сайта — `"hidden": true` — по решению автора, остаётся для регрессионных тестов). Плюс индивидуальные шаблоны преподавателей — в выпадающем списке «Индивидуальные шаблоны» в той же полосе (`"group"` в профиле); сейчас один: «Авраменко В.» (`avramenko_16x9_v01_26`, см. «Индивидуальные шаблоны»). Профиль подходит для шаблонов шириной 10″ высотой 7,5″ (4:3) или 5,625″ (16:9); другой формат требует доработки кода или ИИ-движка.
- **Движки конвертации.** Конвертер по правилам (`converter/`, `"engine": "rules"`) и «пересадка» для индивидуальных шаблонов (`app/reskin.py`, `"engine": "reskin"`). Позже — ИИ-движок. Общие шаги (shrink, verify, превью, памятка) не зависят от движка.
- **ИИ.** Модуль `app/ai/` с общим интерфейсом и провайдерами; первый — Anthropic (Claude), позже, возможно, другие с выбором на сайте. Ключи только из переменных окружения (`ANTHROPIC_API_KEY` и т. п.). Учитывать расход токенов и дневной лимит. Anthropic API недоступен из России — это влияет на выбор сервера.

Максимально минималистичный, ориентир — balenciaga.com (референсы в `../рефы/`): белый фон, чёрный текст, заглавные буквы в навигации и заголовках, тонкие линии-разделители и сетка, без теней и скруглений, мелкие подписи моноширинным шрифтом. ## Конвертер — не переписывать

`converter/` — отлаженный код, который вырос из десятков ручных переносов и правок методистов. Логику переноса не меняй и не «улучшай». Если для приложения что-то нужно поменять (например, пути), меняй минимально и сначала спроси.

Как он запускается (подробно в `docs/README_конвертера_как_запускать.md`):

```
cd converter
python3 convert.py старый.pptx новый.pptx 5.3       # номер урока: «класс.урок»
python3 shrink.py новый.pptx новый_сжатый.pptx 50   # сжимает картинки, только если файл больше 50 МБ
python3 verify.py старый.pptx новый_сжатый.pptx     # сверка слов: MISSING / EXTRA
```

Лимит 18,5 МБ остался от старой среды: конвертер запускали в чате Claude, и файл крупнее не сохранялся в папку. Сайту он не нужен — по решению автора лимит 50 МБ (`SIZE_LIMIT_MB` в `app/pipeline.py`).

Переменные окружения (см. `converter/engine.py`, строки ~16–19):
- `CONV_DIR` — рабочая папка; конвертер ищет в ней `assets/` со стикерами. Папки `assets/` в репозитории нет намеренно (см. «Стикеры» ниже). Задавай `CONV_DIR` = корень проекта.
- `CONV_BASE` — базовая презентация. Всегда задавай явно:
  - 5 класс → `base/ex58.pptx`;
  - 6 класс → `base/ex64.pptx`.
- `CONV_DONOR` — для 6 класса обязательно:
  ```
  {"title":1,"plan":3,"wait":5,"summary":16,"reflection":29,"bye":30,"links":31,"dividers":[4,17],"content":[7,7,26,7],"why":2,"think":6,"title_strip_callouts":true,"title_pic":true,"wait_step":1.34,"wait_center":4.18}
  ```
  Для 5 класса не задаётся (используются значения по умолчанию в `convert.py`).

Номер урока (`6.15`) задаёт тег «6 класс» и «Урок 15». Формат ввода: `^(5|6|7|8|9|10|11)\.\d{1,2}$` (классы 5–11 по просьбе автора; 7–11 берут доноры 6 класса — `grade_aliases` в профиле).

Предмет: конвертер ставит на титул тег «История». Для других предметов `app/pipeline.py` после конвертации меняет текст этого тега (`set_subject`); предмет вводится на сайте или берётся из тега на титуле старой презентации (`detect_subject`, список `SUBJECTS` в `app/texts.py`). Длинный предмет («Обществознание») не влезает в тег — тег расширяется по тексту, теги класса и урока сдвигаются вправо (`widen_tag`).

**Старый шаблон 10×7,5″ (уроки 6–11 классов, разные предметы) — поддерживается с согласия автора.** Слайд того же размера, что новый, кнопки «Вернуться к навигации», ярлыки «Теория» / «Групповая работа» внизу, служебные слайды до титула. Конвертер узнаёт его по ширине слайда (> 8,5″, флаг `WIDE` в `convert.py`): геометрия берётся из файла, титул — первый слайд с тегом «N класс», ярлыки внизу не переносятся, свои правила для плана, отбивок, итогов, прощания и «Использованных источников». Все правила — в чек-листе, раздел 8; эталонов методиста для этих уроков пока нет. Старый шаблон 5–6 классов (8,27×5,9″) переносится байт в байт как раньше — это проверяет регрессия (с 06.11.2026 единственное отличие — неразрывные пробелы после коротких предлогов и союзов, `nbsp` в `convert.py`, во всех уроках). По примерам методиста (9.07, литература 16:9; решение автора 06.11.2026) в старом шаблоне 10×7,5″ и 16:9 ярлыки и номера-стрелки становятся прямоугольниками, карточка красится в пару ярлыка, «Спасибо за внимание!» — заголовком, «Использованные источники» — 14 pt справа от заголовка (`flat_arrows`, `pair_colors`, `thank_you`, `build_links`; чек-лист, раздел 8). Цель автора — со временем переносить всё только в фирменный шаблон; профиль «Сегмент 5–11» с сайта убран (скрыт, остаётся для тестов). Сложные схемы и макеты, где правила не справляются, — кандидаты для ИИ-доработки (этап 7: ИИ — дополнение к конвертеру, не замена).

Сайт отказывает только файлам, уже сделанным в новом шаблоне (тема «Шаблон 5–11 (2026)», `check_input`). Предмет и номер урока ищутся на титуле, где бы он ни стоял (`detect_subject`, `detect_lesson`; тег предмета не из списка берётся слева от «N класс», например «English»).

## Стикеры — старые остаются

Раньше конвертер сам ставил два стикера: «ВАЖНО» (`vazhno.png`) и объёмный «?» (`qmark.png`). В базе стикеров Фоксфорда их около сотни, и методисты подбирают их вручную, поэтому папки `assets/` нет.

Решение автора (05.11.2026): если нового стикера в `assets/` нет, на отведённое ему место ставится старый стикер из исходника (`old_sticker()` в `convert.py`, с его пропорциями и поворотом), а методист потом меняет его на актуальный — это пункт памятки «Проверьте вручную». Списка «Добавьте стикеры» на сайте больше нет. Если когда-нибудь положить файлы в `assets/`, конвертер снова будет ставить новые стикеры сам.

## Жёсткие технические ограничения

- `engine.py` берёт шрифт по пути `/usr/share/fonts/truetype/open-sans/OpenSans-*.ttf`. Он нужен для расчёта переносов строк, поэтому всё запускается только в Docker на Linux с пакетом `fonts-open-sans`. На Mac или Windows без Docker конвертер работать не будет.
- `soffice` (LibreOffice) нельзя запускать параллельно. Задачи обрабатываются строго по одной, через очередь. Пользователь видит своё место в очереди.
- Рендер превью: `soffice --headless --convert-to pdf`, затем `pdftoppm` (пакет `poppler-utils`) → PNG по слайдам + контакт-лист.
- Python-зависимости — в `converter/requirements.txt`. Свои скрипты не называй `inspect.py` и другими именами модулей стандартной библиотеки.
- Загружаемые файлы до ~100 МБ. Временные файлы удалять через N часов (настраивается).

## Что видит пользователь после конвертации

1. Кнопку «Скачать .pptx».
2. Превью всех слайдов (сетка миниатюр, клик — крупно).
3. Сверку текста: если `verify.py` нашёл MISSING-слова, показать их понятным списком («Эти слова есть в старой презентации, но не нашлись в новой»).
4. Замечания к конкретным слайдам — бледным мелким текстом под превью слайда (решение автора); в колонке «Проверьте слайды» — только общие.
5. Памятку «Проверьте вручную» (`MANUAL_CHECKS` в `app/texts.py`, состав — решение автора 05.11.2026): текст в карточках по левому краю, титул под настроение урока, заменить иллюстрации в старом стиле на новые, схемы со стрелками, таблицы, заменить стикеры на актуальные.

При ошибке конвертера — понятное сообщение и кнопка «Сообщить автору» (пока просто показать контакт; адрес задаётся в конфиге). Полный traceback — в лог, не пользователю.

## Стек и развёртывание

- Бэкенд — FastAPI, интерфейс — одна HTML-страница с простым JS (решено). Код должен быть простым, чтобы его мог поддерживать один человек-непрограммист.
- Docker: один `Dockerfile` + `docker-compose.yml`. В образе: python3, зависимости, `libreoffice-impress`, `fonts-open-sans`, `poppler-utils`.
- Доступ закрыт: на первом этапе — общий пароль из переменной окружения; позже, возможно, корпоративный SSO (решает IT).
- Нужна инструкция для IT в `DEPLOY.md`: как собрать, запустить, обновить, где логи.
- Обновление конвертера должно сводиться к: заменить файлы в `converter/` → пересобрать контейнер одной командой.

В `test_inputs/old/` лежат старые презентации, в `test_inputs/reference/` — их переносы, принятые методистом. Для каждой пары:

- `verify.py` не должен показывать расхождений, кроме служебных кнопок старого шаблона и склеенных слов;
- показать мне превью рядом с эталоном, чтобы я сравнил глазами.

Добавь простой скрипт `tests/run_all.sh`, который прогоняет все тестовые файлы.

Сделано: `tests/run_all.sh [--template …]` прогоняет все `test_inputs/old/*.pptx` и сверяет «отпечаток» результата с `tests/baseline/` («совпадает» / «ОТЛИЧАЕТСЯ»). Номер урока — из имени файла, а если его там нет — с тегов титула. У уроков без эталона методиста (шаблон 10×7,5″) отпечаток тоже записывается — чтобы видеть, что правка конвертера их изменила.

### ИИ-доработка: решения автора (30.10.2026)

- Запуск — кнопкой «Доработать с ИИ» на странице результата, уже после обычной конвертации: если превью и так нормальное, ИИ не нужен.

- Модель — Claude Opus 5.5 (`claude-opus-5-5`) через посредника DS Lab (`ANTHROPIC_BASE_URL=https://api.dslab.tech`, ключ — `ANTHROPIC_AUTH_TOKEN` в `.env`; нативный API Anthropic, оплата в рублях: 400 ₽ / 2000 ₽ за 1 млн входных / выходных токенов). Дневной лимит — `AI_DAILY_LIMIT_RUB` в `.env` (пока 1000 ₽, решение автора), расход пишется в `data/ai_usage.json`. Библиотека `anthropic` закреплена на 1.17.0 — она отправляет версию API `2023-06-01`, как требует DS Lab.
- Через DS Lab VPN не нужен (напрямую API Anthropic из России недоступен). Базы стикеров пока нет.
- Как устроено (`app/ai/`): ИИ видит картинки старого и нового слайда и список фигур; два круга — правка и проверка своих правок. Автоматическая проверка геометрии (`problems` в `slides.py`: слово шире плашки, текст выше плашки, текст или таблица на картинке, наложения) подсказывает ИИ, что исправить; если после ИИ таких проблем на слайде больше, чем после конвертера, слайд возвращается к версии конвертера; оставшиеся — в замечаниях «после ИИ: …». Прототип (30.10.2026): 9.23 — 5 слайдов за 55 ₽, 6.19 — 3 за 23 ₽, литература 16:9 — 12 за 110 ₽; 1,5–3 минуты на урок. Прогон из командной строки: `python3 -m app.ai outputs/tests/<профиль>/<урок>`.
- Правила для ИИ — в `app/ai/prompt.md` (их можно править без программиста); составляются по правкам методиста: в `test_inputs/ai_review/<урок>/` лежат «без ИИ», «с ИИ», «исправлено». Первые примеры (06.11.2026): 9.07 (4:3) и «РВШ литература» (16:9). Из них в правила вошло: содержимое сразу под заголовком (не центрировать по вертикали), ярлык вплотную над карточкой, цвет карточки — пара ярлыка (фиолетовый → лавандовый, оранжевый → персиковый), соседние карточки одного размера и на одной линии, короткий текст в карточке по центру по вертикали (`valign` в ответе ИИ), крупные картинки и стикеры, плотные схемы — 12 pt без переносов по частям, лишние линии-связки удаляются.

## Этап 6: фирменный шаблон как база

Сейчас слайды-доноры берутся из готовых уроков (`ex58`, `ex64`). Цель — брать их из самого фирменного шаблона `base/template_4x3_v01_26.pptx` (сейчас 181 слайд). Зачем: больше вариантов титулов, разделителей, планов и рефлексии; выбор титула можно отдать пользователю; при новой версии шаблона достаточно заменить файл.

Что уже известно (подробно — `docs/template/Карта_шаблона.md`):

- слайдов «Поставь на паузу» (`wait`) и «Почему стоит посмотреть» (`why`) в шаблоне нет. Предложи, как их подключить. Мой предпочтительный вариант: собрать одну базу «шаблон + эти слайды из `ex58`/`ex64`» скриптом, а не вручную;
- донорские слайды шаблона содержат тексты-заглушки («Текст», «У короля с королевой…» и др., список в карте) — они не должны попасть в результат. Добавь проверку на них в `verify.py` или отдельным шагом;
- `Builder.finish()` удаляет исходные слайды базы, и python-pptx при сохранении отбрасывает неиспользуемые картинки, поэтому размер базы на размер результата не влияет. Всё равно прогоняй `shrink.py`.

Как делать:
1. Вынеси всё, что относится к шаблону, в «профиль»: папка `templates/<имя>/` с базой, `donors.json` (бывший `CONV_DONOR`), служебными фразами (и, если понадобится, стикерами). Профили `ex58` и `ex64` должны давать ровно тот же результат, что сейчас.
2. Добавь профиль `foxford_5-11_v01_26` на базе шаблона.
3. Функции сборки (`build_title`, `build_plan`, `build_summary` и др.) написаны под устройство фигур на слайдах `ex58`. Для каждого типа проверь, подходит ли донор из шаблона, и поправь сборку минимально. Каждое изменение — с прогоном тестов и сравнением с эталоном этапа 3.
4. Если правило в коде противоречит чек-листу (`docs/Чек-лист_переноса.md`), прав чек-лист; спроси меня.
5. В веб-приложении — выбор профиля и, для фирменного шаблона, выбор титула (миниатюры 5–11).
