# Версия «в браузере» — альтернатива сайту

**Это пробный вариант, а не замена.** Основной вариант — сайт (`app/`) и приложение на компьютере (`desktop/`).
Всё, что относится к этой версии, лежит в папке `browser/`. Если она не приживётся, папку можно удалить целиком —
сайт, приложение, конвертер и тесты от неё не зависят (см. «Как удалить» в конце).

## Что это

Сайт без серверной части: папка обычных файлов. Методист открывает страницу, выбирает файл, шаблон, класс и номер
урока — и получает `.pptx`, сверку текста и памятку. Перенос выполняется **в браузере самого методиста**:
Python вместе с конвертером загружается на страницу (технология Pyodide). Ни Docker, ни сервера с Python не нужно.
Файл урока никуда не отправляется.

Чего нет по сравнению с сайтом:

- **превью слайдов** — его рисует LibreOffice, в браузере его нет. Методист открывает результат в PowerPoint;
  замечания к слайдам показаны списком «Слайд 7 — …»;
- **ИИ-доработки**;
- входа по паролю, очереди, ссылки на результат: результат живёт только в открытой вкладке.

Сам перенос — тот же: страница вызывает `app/pipeline.py` и `converter/` без изменений.
Проверено на тестовых презентациях: результат совпадает с сайтом байт в байт (см. «Проверка»).

## Как пользоваться (автору)

Все команды — из корня проекта, нужен Docker Desktop.

| Что сделать | Команда |
|---|---|
| Собрать (после любой правки конвертера, шаблона или страницы) | `./browser/build.sh` |
| Открыть у себя | `./browser/preview.sh`, затем http://localhost:8766 |
| Проверить на тестовых презентациях | `./browser/tests/run.sh` |
| Выложить на сайт | Commit и Push ветки в GitHub Desktop — дальше GitHub собирает и публикует сам (см. «Публикация») |

Сборка кладёт готовый сайт в `dist/browser/` (около 170 МБ; в git не попадает). Первый раз она скачивает
Pyodide (~15 МБ) в `dist/browser-cache/`.

Открыть `dist/browser/index.html` двойным щелчком нельзя: браузеру нужен адрес `http://…` или `https://…`.

## Публикация (GitHub Pages)

Решение автора (13.11.2026): в шаблонах нет корпоративной тайны, репозиторий и сайт публичные, всё живёт в одном
репозитории. Сайт собирает и выкладывает **сам GitHub**: при каждой отправке (Push) ветки `browser-lite` или `main`
он выполняет `./browser/build.sh` и публикует результат (`.github/workflows/browser-site.yml`, 5–10 минут).
Собранный сайт (~170 МБ) в репозитории не хранится. Поисковикам сайт запрещён (`robots.txt`, `noindex`),
но откроет его любой, у кого есть ссылка.

Настроить один раз (на github.com, в репозитории):

1. Settings → Pages → Build and deployment → Source: **GitHub Actions**.
2. Settings → Environments → `github-pages` → Deployment branches and tags: добавить ветку `browser-lite`
   (или выбрать «No restriction»). Без этого GitHub откажется выкладывать сайт не из `main`.
3. Отправить ветку `browser-lite` (GitHub Desktop → Publish branch / Push origin).
4. Вкладка Actions: дождаться зелёной галочки у «Сайт „в браузере“». Адрес сайта:
   `https://pv19th.github.io/foxford-converter-presentation-pptx/`.

Обновление сайта: поправить → `./browser/build.sh` и `./browser/tests/run.sh` у себя → Commit и Push. Дальше GitHub сам.
Красный крестик на вкладке Actions значит, что сборка не прошла и на сайте осталась прежняя версия.
Если ошибка — «Pages не включён» (ветку отправили раньше, чем настроили Pages): открыть этот запуск → Re-run all jobs.
Контакт для «Сообщить автору» на опубликованном сайте: Settings → Secrets and variables → Actions → Variables →
`SUPPORT_CONTACT` (он будет виден всем).

Свой домен — **сделано 13.11.2026: сайт открывается по адресу `https://converterfoxkont.ru`** (домен у регистратора Рег.ру).
Как это настраивалось (пригодится при смене домена; в зоне .ru имя пишется только латиницей):

1. Купить домен у регистратора (для .ru нужны паспортные данные).
2. В настройках DNS домена у регистратора добавить записи:
   - четыре записи типа `A` для самого домена (`@`): `185.199.108.153`, `185.199.109.153`, `185.199.110.153`, `185.199.111.153`;
   - запись типа `CNAME` для `www` → `pv19th.github.io`.
3. На github.com: Settings → Pages → Custom domain → вписать домен → Save. Когда GitHub проверит DNS и выпустит
   сертификат (от часа до суток), поставить галочку «Enforce HTTPS».

Сначала проверить сайт на адресе `github.io`, потом привязать домен и только после этого рассылать ссылку коллегам.
Перед рассылкой открыть сайт с рабочего компьютера одного из коллег.

## Как устроено

| Файл | Зачем |
|---|---|
| `runner.py` | Запуск в браузере. Вызывает `app/pipeline.process` и подменяет в нём три вещи: шаги конвертера идут не отдельными процессами, а в том же Python; превью не строится; базы шаблонов не собираются (они собраны заранее) |
| `build.py`, `build.sh` | Сборка `dist/browser/`: страница, Pyodide, библиотеки, шрифт Open Sans из Docker-образа, код, базы шаблонов, миниатюры, `meta.json` |
| `web/index.html`, `web/app.js` | Страница. Форма — копия сайта (`app/web/`), без входа, превью и ИИ. Оформление — `app/web/static/style.css` сайта (копируется при сборке) и несколько строк в `web/lite.css` |
| `web/worker.js` | Отдельный поток браузера, в котором работает Python, чтобы страница не замирала. На каждую презентацию — новый поток: так освобождается память |
| `preview.sh` | Открыть собранную версию на своём компьютере |
| `.github/workflows/browser-site.yml` (вне папки) | Указание GitHub: собрать сайт и выложить на GitHub Pages при отправке ветки |
| `tests/` | Проверка: тот же Pyodide запускается без браузера (в Node) и прогоняет `test_inputs/` |

Версии: Pyodide — в `build.py` (`PYODIDE`), `python-pptx` и `xlsxwriter` — из `constraints.txt`, как на сайте.
`lxml` и `Pillow` идут в составе Pyodide; `Pillow` там чуть старше, чем на сайте (сборка печатает обе версии).
Скрытые профили (`"hidden"`) в сборку не попадают.

## Проверка

`./browser/tests/run.sh [профиль …] [--only урок]` прогоняет те же презентации, что `tests/run_all.sh`, и сверяет
«отпечаток» с **эталонами сайта** (`tests/baseline/`). «совпадает» значит: в браузере получается тот же файл,
что на сайте. Результаты — в `outputs/browser/`. Своих эталонов у этой версии нет и быть не должно.

После правок конвертера порядок такой: тесты сайта → новые эталоны (если так задумано) → `./browser/build.sh` →
`./browser/tests/run.sh`.

## Ограничения и что может сломаться

- **Память.** Браузер даёт Python не больше 2–4 ГБ. Чем тяжелее презентация, тем больше нужно памяти (цифры по
  тестовым урокам — в `CLAUDE.md`, раздел «Версия в браузере»). На слабом ноутбуке с десятками вкладок тяжёлый урок
  может не пройти — страница покажет понятную ошибку.
- **Первая загрузка** — около 65 МБ (Python ~15 МБ и база шаблона ~50 МБ). Дальше браузер берёт их из своего кеша.
- **Браузер** нужен современный: Chrome, Edge, Яндекс Браузер, Safari 15+, Firefox 114+.
- **Результат не хранится**: закрыл вкладку — файл пропал, нужно перенести заново.
- **Страница — копия формы сайта.** Если на сайте меняется форма (новое поле, новый вид выбора), правку нужно
  повторить в `web/app.js` и `web/index.html`. Новые шаблоны, варианты слайдов, тексты памятки и список предметов
  подхватываются сами — они берутся из `templates/` и `app/texts.py` при сборке.
- **Новые файлы кода.** Если в `app/` или `converter/` появится новый файл, нужный переносу, его надо дописать
  в список `CODE` в `build.py`. Если `app/pipeline.py` начнёт запускать новую внешнюю программу — в браузере она
  не заработает; `tests/run.sh` это покажет.

## Как удалить

1. Удалить папку `browser/` и файл `.github/workflows/browser-site.yml`.
2. Удалить раздел «Версия в браузере» в `CLAUDE.md` и строку о ней в `README.md`.
3. Если сайт был опубликован: на github.com Settings → Pages → Unpublish site (и убрать домен, если привязан).
4. По желанию удалить локальные папки `dist/browser/`, `dist/browser-cache/`, `outputs/browser/` (в git их нет).

Больше ничего: в `app/`, `converter/`, `tools/`, `tests/`, `desktop/` и `Dockerfile` для этой версии не менялось ни строки.
